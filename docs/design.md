# 冷笑話對話模型：實作設計與驗證

## 專案目標

在 Apple M4 Pro、24 GB 統一記憶體環境下，實作小型語言模型的多輪笑話微調流程，
涵蓋資料驗證、分組切分、QLoRA 訓練、權重選擇、基準比較與本機聊天。
評估重點為教材預測能力及自由回答品質，兩者分開報告。

## 技術架構

- 模型：Qwen3-1.7B 的 MLX 4-bit 版本。
- 環境：Python 3.13、uv、MLX-LM 0.32.2、MLX 0.32.4、Transformers 5.20.2。
- 資料：繁體中文冷笑話、諧音梗與雙關的多輪合成對話。
- 微調：凍結基礎權重，於注意力層加入 LoRA。
- 推論：以歷史訊息串列傳遞上下文，支援串流輸出及歷史清除。

## 模組職責

| 模組 | 職責 |
|---|---|
| 01–03 | 模型試用、單筆教材檢查與前綴切分範例 |
| 04_build_corpus.py | 正式語料驗證、來源分組與 token 長度統計 |
| project_utils.py | 共用路徑、模板、資料驗證及答案 loss 遮罩 |
| 05_train.py | 短程檢查、QLoRA 訓練、指標紀錄及最佳 adapter 保存 |
| 06_evaluate.py | 原始與微調模型比較、留出資料評估及自由多輪展示 |
| 07_chat.py | 本機互動聊天、歷史管理與輸出紀錄 |
| 08_report.py | 根據實際評估結果產生 Markdown 報告 |

## 資料與可重現性

- 固定套件版本、模型 revision 及隨機種子。
- 先依完整對話分組，再展開助手回答前綴；同一來源不可跨 train、valid、test。
- 開發過程已使用的狗狗案例固定歸訓練集，其結果只用於觀察教材記憶。
- 訓練前拒絕空內容、錯誤角色順序及超過 token 上限的樣本。
- 保存分組清單、來源識別碼、檔案雜湊與原始實驗紀錄。
- 版本控制排除基礎模型、虛擬環境及中途 checkpoint，保留最佳 adapter。

## 訓練與評估設計

- 訓練與推論均採非思考模式，檢查 prompt 與答案的 token 邊界一致。
- Loss 只計算最後助手回答，排除 prompt 與 padding。
- 使用短程 smoke test 驗證資料及 GPU 流程，再執行正式訓練。
- 依完整驗證集 loss 選擇權重，不使用測試集選 checkpoint。
- 訓練結束後，以相同生成設定比較原始模型與最佳 adapter。
- 教材前文評估與自由多輪對話分開保存；自由多輪使用模型自身生成的前文。
- 品質報告保留失敗案例，區分 loss 改善、教材記憶與未見主題的回答能力。

## 驗證範圍

- 資料來源分組不重疊。
- Prompt 為完整 token 序列的前綴，目標答案非空。
- Loss 遮罩包含正確答案位置，排除 prompt 與 padding。
- 錯誤角色及空白內容可被攔截。
- 聊天串流、多輪上下文、`/reset` 及 `/exit` 可正常執行。
